# Phase 6 user acceptance checklist

Run this only with a real Chrome 148+ build produced from a dependency-locked checkout.

## A. Install and activation

- [ ] Build/package the extension from the committed lockfile.
- [ ] Load/install the tested package in Chrome 148+.
- [ ] Open an HTTP(S) fixture reader page.
- [ ] Click the toolbar action: the Side Panel opens immediately and transitions from Activating to Ready.
- [ ] Invoke the `_execute_action` shortcut and confirm it follows the same activation path.
- [ ] Open an unsupported Chrome/internal page and confirm the panel reports Unsupported rather than fabricating an active session.

## B. Local Engine setup

For development acceptance only, start the companion with `MTE_ENABLE_FIXTURE_PROFILE=1`; do not treat `fixture-v1` as a production quality result.

- [ ] Open Settings/Options.
- [ ] Grant the exact loopback host permission from the setup button.
- [ ] Probe `/healthz`; verify host-permission/LNA-denied/offline states are distinguishable.
- [ ] Enter a pairing token; confirm it is masked by default and can be revealed only by the explicit control.
- [ ] Pair successfully and inspect capabilities.
- [ ] Select `fixture-v1` for development acceptance; confirm `default-v1` remains blocked without a valid production freeze.
- [ ] Disconnect/re-pair and confirm state recovery.

## C. Translation flow

- [ ] Detect fixture images and confirm visible/near/far candidates are differentiated.
- [ ] Translate a visible candidate and a page batch.
- [ ] Verify real stage/progress is shown; no invented percentage appears.
- [ ] Cancel active work and observe a terminal cancellation state.
- [ ] Reload/close the Side Panel while work runs; work continues and the reopened panel reconstructs state.
- [ ] Disable “show result automatically”; translate and confirm the result is retained while the original remains visible.
- [ ] Enable compact controls and switch original/translation without reprocessing.
- [ ] Restore all originals.
- [ ] Trigger an exact HTTPS CDN permission request; deny it and verify the screenshot fallback path where allowed.

## D. Safety/privacy

- [ ] Confirm target language cannot be changed away from Arabic.
- [ ] Confirm SFX policy is visible but cannot be changed away from preserve-original.
- [ ] Copy diagnostics and confirm they contain no full page URL/title, OCR text, translation text, token/key, image bytes, or filesystem path.
- [ ] Confirm privacy disclosure changes according to the selected Engine profile capability descriptor.
- [ ] Confirm no external telemetry request is generated by the extension UI.

## E. i18n/accessibility

- [ ] Test English and Arabic complete UI, including RTL layout.
- [ ] Verify Japanese/Korean/Simplified-Chinese/Traditional-Chinese Chrome metadata fallback structure.
- [ ] Operate all controls using keyboard only.
- [ ] Check focus indicators and accessible button names with a screen reader.
- [ ] Enable reduced motion and confirm progress/loading UI does not depend on animation.
- [ ] Resize/move the Side Panel and test long error/domain strings without unusable clipping.

## Exit

Phase 6 passes only when a non-developer can complete A–E on a clean supported machine. Passing with `fixture-v1` proves UI/companion workflow only; production translation readiness separately requires Phase 5B Gate D.

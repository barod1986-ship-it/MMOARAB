# Production ML Benchmark & Model Pinning Gate — REV10

This gate sits **between Phase 5 and Phase 6**. It does not ship model weights and it does not claim `default-v1` is production-ready.

## Why the gate exists

Vendor OCR numbers are useful candidate evidence, not a manga/manhwa acceptance test. The production profile is frozen only from a legal project corpus, measured end-to-end, with exact artifact digests and reviewed model/checkpoint provenance.

## Required inputs

1. External sealed `corpus-manifest.json` plus image/annotation files. Every page must use corpus schema v2 and bind its source identity plus reviewed rights record by exact SHA-256. The rights record must explicitly authorize benchmark and production-V1 qualification use; a manifest boolean alone is not accepted.
2. Explicitly acquired local model artifacts. Automated primary-source acquisition is separate, allowlisted and content-addressed; nothing is fetched by the benchmark or runtime path.
3. `model-candidates-v1.json` plus one content-addressed provenance receipt per planned artifact. Derived LaMa/AOT wrappers additionally bind source-checkpoint SHA-256 and converter revision.
4. Immutable V1 candidate identity plan `engine/benchmark/candidate-plan-v3.json`. The older `candidate-plan-v1.json` and `candidate-plan-v2.json` are retained as historical planning evidence only and are not the active V1 gate. v3 removes the Japanese primary/fallback exception so every OCR language uses the same deterministic quality rule.
5. A ready content-addressed `benchmark-run-plan.json` produced only after corpus/artifacts/receipts validate.
6. A sealed human-review record created from `engine/benchmark/benchmark-review.template.json` and bound to the ready `runPlanSha256`.
7. Schema-v2 raw benchmark evidence generated by `engine/scripts/execute_benchmark.py`; hand-authored schema-v1 raw files are historical/fixture-only and cannot pass the production gate with a ready run plan.
8. Versioned release policy `benchmark-thresholds-v3.json`. `benchmark-thresholds-v1.json` and `benchmark-thresholds-v2.json` are retained unchanged as superseded historical policies. v3 changes only the active selection policy needed to remove predetermined Japanese OCR preference.

A freeze is rejected if the corpus is undersized/unreviewed, source-rights evidence is missing/tampered/non-qualifying, real-domain language minimums are replaced by synthetic pages, candidate identity differs from the frozen candidate plan, schema-v2 executor evidence or its executor-source pin does not match the ready run plan, the raw/report evidence is not bound to that run plan, an artifact/receipt is missing or hash-mismatched, benchmark use is unapproved for any measured artifact, selected model/checkpoint licensing/provisioning is unresolved, deterministic candidate selection does not match the report, translation/inpainting quality gates fail, or any SFX/uncertain destructive-edit safety metric is non-zero.

## Safety metrics that are never tunable

All must be exactly zero:

- ground-truth SFX sent to translator;
- erase/inpaint overlap over independent ground-truth SFX pixels;
- changed pixels inside ground-truth SFX after final encode/decode;
- destructive editing of `uncertain` blocks;
- protected conflicts silently overwritten.

The role gate must protect **100% of independently annotated SFX blocks** for the frozen production revision. This protected-SFX recall is recomputed from per-block raw evidence; it is not accepted as a caller-supplied aggregate.

Each raw SFX/uncertain row carries the corpus `pageId`, annotation `blockId`, language and destructive-edit measurements. The release gate rebuilds the normalized report from the supplied raw file and requires the reported SFX block keys to match the independently hashed corpus annotations exactly. A hand-edited report, omitted SFX block, duplicate evidence row or invented block therefore blocks the freeze.

## Current repository state

The harness, sealed-corpus workflow, immutable candidate plan, content-addressed artifact receipts, executor-source-pinned preflight run plan, schema-v2 formal executor, deterministic machine-trace reconstruction and tamper-evident freeze mechanism are implemented. Every benchmarked winner or loser must have approved benchmark use, verified local bytes and a matching provenance receipt; selected shipping artifacts also need approved artifact-license/provisioning state. The production corpus and model weights are intentionally absent. Therefore no ready benchmark run plan or valid `production-profile-freeze.json` is committed and `default-v1` remains non-ready.

See `docs/PRODUCTION_ML_ARTIFACT_AND_CORPUS_INTAKE.md` for the acquisition/sealing procedure and `docs/PRODUCTION_CORPUS_RIGHTS_CHAIN.md` for corpus source/rights qualification.

The complete fail-closed chain is intentionally two-phase. `engine/scripts/run_production_qualification.py` performs reviewed acquisition/intake and creates one stable ready run plan. After the human benchmark review is sealed to that exact `runPlanSha256`, `engine/scripts/execute_prepared_qualification.py` resumes the same workspace without reacquisition/re-intake, executes the benchmark, deterministically rebuilds/evaluates the report, and creates the production freeze only when the gate passes. Automated acquisition is explicit and never substitutes for artifact review records.

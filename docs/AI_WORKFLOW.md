# سير العمل مع GitHub والذكاء الاصطناعي

## نقطة البداية

دورة المراجعة الثانية تبدأ من المرحلة 1:

- `rathena-master/npc/cities/izlude.txt`
- `rathena-master/npc/cities/prontera.txt`

## التنفيذ المباشر

تفتح Pull Request عند بدء المرحلة، وتبقى مفتوحة أثناء إضافة التصحيحات والمزامنة وتحديثات القاموس. تصبح جاهزة للدمج بعد اكتمال نطاق المرحلة ونجاح التحقق.

## دورة كل مرحلة

1. حدّث `main` محليًا.
2. أنشئ فرعًا باسم واضح، مثل `review-cycle-2-stage-001-prontera-izlude`.
3. افتح Pull Request للمرحلة مباشرة.
4. اقرأ الملفات الإلزامية المذكورة في `AGENTS.md`.
5. قارن الملف العربي بالمرجع الإنجليزي حسب البنية والسياق لا حسب أرقام الأسطر.
6. افحص الأنظمة المرتبطة وفق `docs/SYNC_SCOPE.md`.
7. ابحث في المصادر الرسمية والموثوقة عند الحاجة ووثق النتيجة.
8. حدّث القاموس أو سجل أن تحديثه غير مطلوب.
9. شغّل:

```bash
python tools/validate_repository.py
python tools/validate_terminology_policy.py
python tools/validate_translation_content.py --base origin/main
```

10. راجع `git diff` وخاصة الأوامر والمعرفات والترميز.
11. حدّث Pull Request بنتائج المراجعة وعدد التعديلات.
12. انتظر نجاح Workflow باسم `Repository QA`.
13. فسّر أي تحذير بنيوي قبل الدمج.
14. ادمج ثم احذف فرع المرحلة.

## الاستيراد الأول

لا تبدأ المرحلة 1 من مستودع لا يحتوي ملفات اللعبة. شغّل `tools/sync_clean_baseline_windows.bat` من هذه الحزمة أولًا، ثم راجع فرع الاستيراد وادمجه.

## تنبيه الترميز

ملفات CP1256 تعدل محليًا بأداة تقرأ وتكتب بالترميز الأصلي. لا تستخدم محرر GitHub على الويب لهذه الملفات.

# سير العمل مع GitHub والذكاء الاصطناعي

## الفروع

- `main`: النسخة المستقرة المعتمدة فقط.
- فرع مستقل لكل مرحلة، مثل `ai/stage-293-guides-lighthalzen`.

## دورة المرحلة

1. حدّث `main` محليا.
2. أنشئ فرع المرحلة.
3. اطلب من الـAI قراءة:
   - `AGENTS.md`
   - الملف العربي المستهدف
   - الملف الإنجليزي المطابق
   - `glossary/master_glossary.csv`
   - الملفات المرتبطة فقط
   - `docs/progress/PROJECT_STATUS.md`
   - `tracking/PROJECT_STATE.json`
4. نفّذ التعديل مع الحفاظ على الترميز ونهايات الأسطر.
5. شغّل أداة التحقق.
6. راجع `git diff`، خصوصا الأوامر والمعرفات والترميز.
7. أنشئ commit واحدا واضحا.
8. افتح Pull Request، راجعه، ثم ادمجه بطريقة Squash أو Commit واحد.
9. احذف فرع المرحلة بعد الدمج.

## استيراد اللقطة النظيفة لأول مرة

لأن مستودع GitHub الحالي يحتوي تاريخ المراحل السابقة، لا تستبدل `main` مباشرة. فك حزمة `MMOARAB_GitHub_Ready_Stage_292.zip` محليا ثم شغّل `tools/sync_clean_baseline_windows.bat`. سينشئ فرع استيراد مستقل ويرفع الملفات الفعلية دون ZIP أو تقارير أو نسخ احتياطية.

## لماذا لا نرسل ZIP كاملا بعد الآن؟

Git يعرض للـAI والمراجع الملفات المتغيرة فقط، ويحفظ جميع النسخ السابقة ويمكن الرجوع إليها، فلا حاجة إلى نسخ احتياطية داخل المشروع.

## تنبيه الترميز

Git يخزن البايتات دون تغيير، لكن بعض محررات الويب وأدوات الذكاء الاصطناعي تفترض UTF-8. ملفات CP1256 يجب تعديلها محليا أو بواسطة وكيل يعمل على نسخة مستنسخة من المستودع ويستخدم قراءة وكتابة صريحة بالترميز الأصلي.
